# Project Manager

無需手動維護即可保持專案井然有序。掃描郵件、貼上指令或上傳檔案——Project Manager 自動讀取並更新對應的專案記錄、日誌和時間線。

## 擅長做什麼

- **郵件分類** — 掃描郵件資料夾，找出與專案相關的郵件，自動路由到正確的專案
- **建立專案** — 一條指令即可產生完整的資料夾結構（README、干係人清單、時間線、日誌）
- **更新專案** — 自動追加日誌條目、更新狀態、更新里程碑、複製新附件，無需手動操作
- **干係人管理** — 追蹤每個專案的參與者，保持聯絡方式和角色資訊最新
- **彙總報告** — 日報摘要、週報、單一專案深度分析、跨專案狀態看板和干係人簡報
- **查詢** — 用自然語言提問任意專案，返回結構化 Markdown 報告

## 工作原理

Project Manager 使用基於 Workspace 的專案儲存。每個專案位於 `projects/YYYY/project-name/`，包含 `README.md`、`people.md`、`timeline.md`、`logs/` 和 `attachments/` 目錄。日誌條目按日期組織在 `logs/` 內。

掃描郵件時，它讀取郵件資料夾中的 `INDEX.md` 進行高效分類，深度讀取相關郵件，然後自動建立或更新對應的專案。不需要分別觸發建立和更新——掃描會自動串聯執行。

沙箱執行 `oneshot`——每次對話使用全新容器，沒有背景狀態。所有專案記錄儲存在 Workspace 中，跨工作階段持久保留。

## 怎麼寫好 Prompt

**掃描郵件時，指定資料夾。** 告訴 Project Manager 要掃描哪個日期資料夾：「掃描今天的郵件。」它負責分類處理。

**手動更新時，盡量具體。** 「在 Acme 網站專案記錄一通與 Alice 的電話，她確認了 5 月 31 日的截止日期。」這樣的描述足以產生一條完整的日誌。

**請求報告時，說清楚你要什麼。** 「產生本週的報告」或「總結 Acme 專案」就夠了——它知道各種格式。

**範例：**

> 掃描今天的郵件並按專案分類。

> 建立新專案：Acme 網站改版。負責人：Alice。截止日期：5 月 31 日。預算：5 萬美元。

> 在 Acme 改版專案記錄一次與 Bob（ACME）的會議。我們審查了首頁設計稿並批准了配色方案。下一步：Alice 在週五前寄送最終素材。

> 產生本週的專案彙總報告。

> 目前所有進行中專案的狀態是什麼？

## 能力速覽

| 能力 | 說明 |
|------|------|
| 郵件掃描 | 基於 INDEX.md 的 IMAP 分類，自動路由到專案 |
| 專案結構 | README、干係人、時間線、日誌、附件——全部自動產生 |
| 報告類型 | 日報摘要、週報、專案概覽、狀態看板、干係人簡報 |
| 查詢 | 自然語言提問 → 結構化 Markdown 報告 |
| 沙箱 | `claude` 映像（無 VNC），2 GB 記憶體，`oneshot` 生命週期 |
| Workspace | 永久儲存——所有專案記錄無限期保留 |
