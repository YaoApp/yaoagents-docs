# 创建 Robot

从零开始配置一个 Robot，大约需要五分钟。本文逐字段说明每项设置的作用。

## 开始之前

- Yao Engine 已运行，Yao Agents 已连接
- 至少配置了一个 AI 模型（Settings → Models）
- 知道你想让 Robot 做什么——哪怕只是个大概描述也够了

---

## 第一步 — 打开 Mission Control，添加 Robot

从左侧边栏打开 **Mission Control**，你会看到 Robot 列表（第一次则为空）。

点击右上角的 **+ Add Task Agent**。

![Mission Control — 含有 Add Task Agent 按钮的 Robot 列表](https://assets.yaoagents.com/en/mission/01-mission-list-en-$__THEME.png)

---

## 第二步 — 填写 Basic 标签页

**Basic** 标签页设置 Robot 的基本信息和工作模式。

![Robot 设置 — Basic 标签页](https://assets.yaoagents.com/en/mission/02-mission-create-basic-en-$__THEME.png)

**Name（名称）** — 起一个清晰、有描述性的名字，这是你在列表和日志中看到的名称。示例："每日市场简报"、"每周报告生成"、"支持邮件分拣"。

**Workspace（工作区）** — 选择 Robot 运行的沙盒环境。每个工作区有独立的文件和上下文。如果希望 Robot 的文件与聊天 Expert 隔离，使用独立工作区。

**Work mode（工作模式）** — 两个选项：
- **Autonomous** — 按计划或事件触发，无需人工介入
- **On Demand** — 每次由你手动启动，适合需要控制启动时机的任务

**Reports to（汇报对象）** — 指定谁接收 Robot 的输出结果，可以是用户账号或另一个 Robot。正确设置可确保结果送达正确的地方。

> 💡 不确定选哪个工作模式？先用 **On Demand**。测试满意后再切换到 Autonomous。

---

## 第三步 — 配置 Identity 标签页

**Identity** 标签页定义 Robot 做什么，以及它能用什么。

![Robot 设置 — Identity 标签页，含角色描述和资源分配](https://assets.yaoagents.com/en/mission/02-mission-create-identity-en-$__THEME.png)

**角色描述** — 用日常语言描述 Robot 的工作职责，要具体说明：
- 它负责什么
- 处理什么输入（邮件主题、URL、文件类型等）
- 产出什么结果（报告、摘要、邮件等）

不知道从哪里写起？点击 **Generate**——它会根据你填的名称自动起草一份角色描述。

**AI Experts** — 选择这个 Robot 在执行管道中可以调用的 AI Expert。分析市场数据的 Robot 应该配 Market Scout；发送邮件报告的应该配 Postman。

**Tools（工具）** — 选择 Robot 可以调用的额外工具（网络搜索、文件读取、API 连接器等）。

> 💡 **让资源与角色匹配。** 把它想象成招聘：你不会让人做财务分析却不给他看数据的权限。清晰的职责描述加上合适的 Expert 和工具，是 Robot 能稳定工作的关键。需要发邮件就给它 Postman，需要搜索网络就加搜索工具。

---

## 第四步 — 保存并运行

完成后点击 **Save Changes**，Robot 出现在 Mission Control 列表中。

第一次运行：
- 在列表中选中 Robot，打开其 Active 视图
- 点击 **Assign Task** — 右侧弹出面板，输入任务描述
- Robot Host 读取描述，确认目标，你批准后管道启动

在进度视图中实时观察每个阶段的执行状态。→ [进度与结果](/docs/zh-cn/mission-control/progress-and-results)

---

## 第五步 — 配置集成（可选）

打开 **Integrations** 标签页，将 Robot 接入消息平台或作为 API 暴露出去。

![Robot 设置 — Integrations 标签页](https://assets.yaoagents.com/en/mission/02-mission-create-integrations-en-$__THEME.png)

**消息平台** — 接入微信、Telegram、Discord、钉钉或飞书。粘贴平台凭证后，用户可以直接在那个应用里和 Robot 对话。

**API 访问** — 每个 Robot 自动获得一个兼容 OpenAI 接口的 Chat Completions 端点。可以从任何 OpenAI SDK、自动化工具或内部系统调用它来触发 Robot。

---

## 高级设置（可选）

Robot 运行正常后，可以在 **Advanced** 标签页进行精细调整。

![高级设置 — 收件人、并发、执行管道 Agent 和开发者选项](https://assets.yaoagents.com/en/mission/02-mission-create-advanced-2-en-$__THEME.png)

- **Additional Recipients** — 在默认的"汇报对象"之外添加更多邮件收件人
- **Concurrency** — 设置高并发 Robot 的最大同时运行数和队列大小
- **Execution Pipeline** — 将管道任意阶段（Host Agent、Goals、Tasks、Delivery）的默认 Agent 替换为自定义 Agent
- **Developer Options** — 在交付时推送结果到 Webhook URL，或调用 Yao Process

→ [替换阶段 Agent](/docs/zh-cn/mission-control/execution-pipeline/replacing-stage-agents)

## 常见问题

**Robot 运行了，但结果很差**
回到 Identity 标签页重新审视。角色描述是最关键的因素——写得更具体一些，同时检查分配的 AI Expert 和工具是否真的匹配任务需要。

**Robot 没有把结果送到任何地方**
检查 Basic 标签页的 **Reports to** 字段，以及 Identity 标签页中是否列出了 Postman 或对应的交付 Expert。

**我触发了 Robot，但什么都没发生**
如果工作模式是 Autonomous，它只按配置的计划运行。切换到 On Demand 或从控制台手动触发。
