# Project Manager

手動メンテナンス不要でプロジェクトを整理します。メールをスキャンし、指示を貼り付け、ファイルをアップロードするだけで、Project Manager が自動で対応するプロジェクトの記録、ログ、タイムラインを更新します。

## 得意なこと

- **メールの仕分け** — メールフォルダをスキャンして、プロジェクト関連メッセージを見つけ、適切なプロジェクトに自動振り分け
- **プロジェクト作成** — 一つの指示から完全なフォルダ構造（README、ステークホルダーリスト、タイムライン、ログ）を構築
- **プロジェクト更新** — ログエントリを追加し、ステータスを更新、マイルストーンを更新、新しい添付ファイルをコピー——手動操作不要
- **ステークホルダー管理** — 各プロジェクトの関係者を追跡し、連絡先と役割情報を最新に保つ
- **サマリーレポート** — 日次ダイジェスト、週次サマリー、プロジェクト詳細分析、横断ステータスボード、ステークホルダー向け簡報
- **クエリ** — 任意のプロジェクトについて自然言語で質問し、構造化された Markdown レポートを取得

## 仕組み

Project Manager は Workspace ベースのプロジェクトストアを使用します。各プロジェクトは `projects/YYYY/project-name/` に、`README.md`、`people.md`、`timeline.md`、`logs/`、`attachments/` ディレクトリとともに配置されます。

メールをスキャンする際、メールフォルダ内の `INDEX.md` を読んで効率的に仕分けし、関連メッセージを詳細に読んだ後、対応するプロジェクトを自動的に作成または更新します。作成と更新を別々にトリガーする必要はありません。

サンドボックスは `oneshot` で実行——会話ごとに新しいコンテナを使用します。すべてのプロジェクト記録は Workspace に保存され、セッションをまたいで永続します。

Docker サンドボックスが有効でない場合、タスクは Yao Engine がインストールされたマシン上で直接実行されます。

## 良いプロンプトの書き方

**メールスキャン時はフォルダを指定する。** どの日付フォルダをスキャンするか伝えてください：「今日のメールをスキャンして」。仕分けは Project Manager が行います。

**手動更新時は具体的に。** 「Acme ウェブサイトプロジェクトで Alice との電話を記録して。5月31日の締め切りを確認した。」これで適切なログエントリを書くには十分です。

**レポートを依頼する際は何が欲しいか指定する。** 「今週のレポートを生成して」や「Acme プロジェクトをまとめて」で十分——フォーマットは理解しています。

**例：**

> 今日のメールをスキャンしてプロジェクトに分類して。

> 新しいプロジェクトを作成：Acme ウェブサイトリデザイン。担当：Alice。締め切り：5月31日。予算：5万ドル。

> Acme リデザインプロジェクトに Bob（ACME）との会議を記録して。ホームページのモックアップをレビューして配色を承認した。次のステップ：Alice が金曜日までに最終アセットを送付。

> 今週のプロジェクトサマリーレポートを生成して。

> 現在進行中のプロジェクトの状況は？

## 機能一覧

| 機能 | 詳細 |
|------|------|
| メールスキャン | INDEX.md 経由の IMAP 仕分け、プロジェクトに自動振り分け |
| プロジェクト構造 | README、ステークホルダー、タイムライン、ログ、添付——すべて自動生成 |
| レポートタイプ | 日次ダイジェスト、週次、プロジェクト概要、ダッシュボード、ステークホルダー簡報 |
| クエリ | 自然言語の質問 → 構造化 Markdown レポート |
| サンドボックス | `claude` イメージ（VNC なし）、2 GB RAM、`oneshot` ライフサイクル |
| Workspace | 永続保存——すべてのプロジェクト記録は無期限に保持 |
